# 工具面板终端插件设计

状态：Q1～Q19 已确认并获准实现；实现已落地，平台验收范围见 [验证记录](terminal-plugin-validation.md)。

## 已确认的需求

- 外部插件代码放在 `aibo-plugins` 仓库；必要时可以扩展 `aibo` 宿主。
- 终端嵌入 Aibo 工具面板，支持用户交互输入与输出。
- 尽量支持 macOS、Windows、Linux；目标平台不等于已经通过三端验证。
- 打开终端时运行当前用户配置的默认 shell，而非固定使用系统出厂 shell。
- 终端归属“工作区＋窗口”，同一窗口内同一工作区的聊天会话共享一组终端；不同窗口即使打开同一工作区也使用各自独立的终端，不提供跨窗口共享或输入接管。新终端从工作区根目录启动。
- 支持多个终端，以标签切换；首版不做分屏。
- 隐藏工具面板或切换同一工作区的聊天会话不结束终端进程。
- 关闭终端结束对应进程；退出 Aibo 结束全部终端。重启后不承诺恢复先前运行的程序。
- 首版终端仅供用户手动操作；不向 Agent 提供读取输出或发送命令的入口，Agent 继续使用自身的命令执行工具。
- 支持完整交互式终端，包括 vim、top、交互式 CLI、Ctrl+C、尺寸变化、彩色输出、中文输入和复制粘贴；首版不做搜索、分屏和自定义快捷键。
- 切换工作区时，原工作区终端继续运行，面板仅展示当前工作区的终端；切回时显示原终端。
- 显式关闭工作区时结束当前窗口内该工作区的全部终端；停用插件时结束该插件的全部终端。
- 关闭标签、关闭工作区、停用插件或退出 Aibo 时，若有受影响的存活终端，统一确认一次并说明影响范围；不猜测进程的重要性。隐藏面板与切换标签、工作区无需确认。
- shell 自行退出或启动失败后，保留标签及已有输出，显示退出状态并提供“重新打开”；不自动重启。重新打开按新终端规则从工作区根目录启动。
- 插件负责完整终端，包括渲染、shell 发现与启动、PTY、输入输出、标签和交互状态；宿主提供通用容器、授权、通信与生命周期监督。见 [ADR-0001](adr/0001-plugin-owned-terminal.md)。
- macOS、Linux 自动跟随当前用户登录 shell；Windows 优先跟随 Windows Terminal 的默认 profile，首版自动识别本机 shell。遇到 WSL、远程连接或无法解析的 profile 时提示选择本机 shell，不静默切换为 PowerShell。
- 默认 shell 无法找到或启动失败时，显示具体原因，提供 shell 路径及参数设置，保存后允许重试。手动配置优先于自动识别，并提供“恢复跟随系统”。
- 插件只在内存保留有限滚动历史，不将终端输出写入聊天历史或终端日志文件；退出 Aibo 后清空输出与标签。此规则不改变 shell 自身的命令历史配置。
- 手动终端以当前系统用户权限运行，独立于聊天的执行权限，不继承聊天只读模式，也不逐条审批用户输入。工作区是初始目录和归属范围，不是文件访问沙箱。
- 插件界面故障时保留后台终端，重新加载界面后连接原实例，仅恢复仍在内存中的内容；插件后端故障时清理所属进程并显示失败，不自动重启 shell。
- 插件安装包携带所需运行依赖，用户无需另装 Node 或编译工具。明确最低宿主版本，不兼容时提示升级；最低版本须在新合同实际落地后确定，不虚构已发布支持。
- 三端均实现并提供构建，按实际测试记录支持情况；未完成真实验证的平台标注为实验性。

### 窗口归属的生命周期

关闭窗口时结束该窗口在所有工作区中的终端，并按既定规则对存活终端统一确认一次；不影响其他窗口。切换工作区只改变当前窗口展示的终端，不结束该窗口原工作区的后台终端。窗口身份用于当前运行期的归属，不用于重启恢复标签或进程。

术语见 [领域语言](../CONTEXT.md#工具面板终端)。

## 当前宿主调查

- 当前 sidebar 提供 collection、detail、settings、inspector 语义，不允许外部插件任意注入 DOM 或组件，参见宿主 `docs/plugin-development.md`。
- 当前源码调查尚未发现 PTY、ConPTY 或 xterm 实现；完整交互终端需要新增相应能力。
- 已有 capability protocol 2.1 的 stream/control 基础，参见宿主 `packages/plugin-protocol/src/capability.ts` 与 `src-tauri/src/plugin_runtime.rs`；不应误认为宿主完全没有双向流机制。
- 现有流消费存在 capability event 持久化路径，参见宿主 `src-tauri/src/capability_broker.rs`；终端原始输出不得直接进入该持久化路径，需采用符合内存保留规则的传输机制。
- Windows Terminal 的默认 profile 与 Windows 的默认终端应用是不同设置；前者才关联运行的命令。参见 [Microsoft 启动设置](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/startup)及 [profile 设置](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-general)。

## 实现时需要细化并验证的技术事项

- 通用隔离工具视图、前后端通信和运行实例合同的具体 schema、版本与最低宿主要求；不通过插件 ID 特判提供终端能力。
- 窗口、工作区、插件运行代际与终端身份的校验，以及视图卸载与后台运行解耦。
- PTY 依赖、各 OS/架构打包、系统 shell 发现及启动参数；所选实现须符合已经确认的产品行为。
- 原始输入输出、尺寸变化、退出通知、背压、有限缓存及故障清理机制；不得持久化终端正文。
- 进程清理的三端实际覆盖范围，尤其后台子进程、插件崩溃与强制结束场景；不得将未经验证的清理能力写成保证。

若技术调查发现无法兑现已确认行为，应说明冲突并重新讨论对应决策，不能静默缩减范围。

## 验收范围

- 插件可安装、启用并从工具面板打开；旧宿主不兼容时给出明确提示。
- 三端分别核对默认 shell、手动覆盖、无法识别、启动失败及工作目录。
- 真实桌面验证交互式 CLI、vim/top、Ctrl+C、尺寸变化、中文输入与复制粘贴。
- 验证多标签、同窗口聊天切换、工作区切换和不同窗口终端隔离。
- 验证关闭取消和确认、工作区/窗口关闭、插件停用与应用退出对正确范围的终端生效。
- 验证界面重新连接、后端故障清理、退出状态展示及用户手动重新打开。
- 验证终端输出不进入聊天/事件持久化或终端日志文件，且重启不恢复标签和输出。
- 按仓库规范运行插件和宿主 verify，并补充合同、原生与桌面测试；记录版本、OS/架构、实测结果和未验证项。当前仅完成设计文档，以上均未实施或验收。

## Q12 架构选择

- **宿主提供终端基础设施**：宿主负责可信终端渲染、PTY、shell 发现与运行实例；外部插件提供工具入口、操作和配置。与现有受限呈现方向一致，原生适配集中在宿主；终端引擎升级需要宿主发布。
- **插件管理完整终端（已选）**：插件携带终端前端和 PTY 后端，负责 shell 发现、交互状态及子进程管理。宿主仍需增加可承载插件终端前端的隔离自定义视图、受控通信桥和按“工作区＋窗口”归属的长驻实例合同，监督退出与停用清理。插件可独立升级终端引擎，但需承担各 OS/架构原生依赖的打包和验证。
- 后一种方案不能直接套用当前 Presentation Worker：当前入口返回受限视觉树，不能运行依赖 DOM 的完整终端前端。插件前端也不应直接获得任意宿主原生命令调用权，进程访问应通过已授权的后端边界。
- 两者都需要宿主扩展；差别在于宿主增加终端专用基础设施，还是增加可供终端及其他复杂工具使用的通用插件视图和运行机制。用户已选择插件管理完整终端，决策见 ADR-0001。
