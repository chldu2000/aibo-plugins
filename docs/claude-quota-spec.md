# Claude Code 订阅额度映射

状态：设计已由用户确认，实现完成，验证记录见文末。

## 已确认的产品行为

2026-10-08，用户确认以下选择：

- 通过上游事件更新额度；本次不增加打开会话时的主动查询或手动刷新。
- 展示上游实际提供且具有有效利用率的已知订阅额度窗口，包括全模型的 5 小时、每周窗口和有数据的模型专属窗口。明确标注模型，不补造缺失窗口，不从 token 消耗推算额度。
- 后续事件缺少某个窗口时，保留该窗口最近一次有效观测值。
- 到达观测值的重置时间而尚无新数据时，该窗口显示未知，不推算为剩余 100%。
- 允许为通用用量合并接口与未知状态展示配套修改宿主和 SDK；Claude 专有字段解析留在 cc 插件。
- 观测值按会话和当前运行实例隔离，不跨会话共享，不跨应用重启或重新连接恢复；新实例等待新事件。
- 展示文案说明数值为最近观测，因为其他会话也可能消耗同一账号的额度。
- 有有效比例但无重置时间时，显示最近观测的比例并标注“重置时间未知”，不猜测截止时间；保留范围同运行实例隔离规则。

术语见 [领域语言](../CONTEXT.md)。

## 已核实的实现约束

- 当前插件依赖的 Claude ACP 0.81.2 在具有上下文用量时，将原生 `rate_limit_event.rate_limit_info` 转发到 `usage_update._meta["_claude/rateLimit"]`。
- 宿主 ACP adapter 当前仅映射上下文和费用；每次 `usage.updated` 发送完整 usage 快照。额度映射必须与后续 token、上下文更新共存。
- 宿主用量模型与状态栏已支持有效数值额度；其当前模型要求数值 `usedPercent`，尚不能直接表达一个可见的未知额度窗口。
- 供应方字段解释属于插件，宿主与共享 SDK 仅承载通用用量语义。

## 映射与兼容

- 优先采用 `unifiedWindows` 的有效比例；同一窗口缺少有效比例时，回退到顶层 `rateLimitType` 与 `utilization`。
- 本次支持 `five_hour`、`seven_day`、`seven_day_opus`、`seven_day_sonnet`；额外付费窗口、未知类型及只有允许/拒绝状态的事件不产生比例。
- 事件 `utilization` 必须为有限的 0..1 数值，乘 100 得到 `usedPercent`。不混用结构化查询接口的百分比单位。
- `resetsAt` 为 Unix 秒；无效或缺少时间按未知处理。`observedAt` 为本次接收时间，表示最近观测。
- cc 插件提供纯映射函数，宿主 SDK 0.1.10 的 `mapUsage` 扩展钩子在校验当前会话、运行代际与非历史回放之后调用；同 ID 的窗口替换，省略窗口保留。
- SDK 后续上下文、费用与回合 token 更新继续发送完整合并快照。关闭、断连和重连清理旧观测，recovery 不保存额度。
- 宿主按最近的未来重置时间调度刷新，不发查询请求。所有会话的事件更新各自缓存，选择会话时重新计算有效性。
- 宿主内部将已过期窗口投影为未知。对外呈现的原 `limits` 仍只含数值比例，新增 `unknownLimits` 传递过期窗口，防止旧呈现把空值误算为 100%。旧外部呈现不显示未知窗口，更新后的共享工作台显示“额度未知”。
- 未知重置时间保留在提示中；当前数据没有跨账号共享或持久额度缓存。

## 交付范围

- cc 插件 0.4.7，需要包含本改动的宿主 SDK 0.1.10。旧宿主不可仅安装新插件获得本功能。
- 共享外部工作台 0.2.3；外部 Material 3 / shadcn 包 0.4.2。
- SDK 尚未发布时使用 `AIBO_SDK=local pnpm run verify` 构建插件。默认 registry 构建需等待对应 SDK 发布。
- 只交付源码和本地产物，不发布、不替换用户正在使用的安装。
- 不新增权限、网络请求或主动订阅额度查询。
